# 建筑提取错误分析报告（W5）

> **数据**：WHU 航拍子集 `WUH_sub25/test`，604 张 / 512×512 瓦片（25% 抽样，seed 11）
> **模型**：U-Net(ResNet50+scSE)，CE+Dice，25 轮，512 输入；对照模型 SegFormer-B1
> **评估口径**：像素级全局混淆矩阵（不是逐图平均），与项目主表一致
> **全部数字可由 `out/error_stats.json` 与 `out/error_images.csv` 复核**
> **生成日期**：2026-10-25

---

## 0 摘要：七条结论

1. **主体质量**：test 604 张全局 **前景 IoU 0.8603 / mIoU 0.9211 / P 0.9240 / R 0.9258 / pixel_acc 0.9838**；逐图 IoU 中位 0.8686、P10 0.7388、P90 1.0000，214 张 >0.9。
2. **误差的主体不是"漏了一栋楼"，而是"边界带里的一圈"**：把 `FN+FP` 总误差 2,567,543 像素分成五桶后，**69.2% 落在 GT 边界 ±3 px 的窄带内**（内缩 36.9% + 外扩 32.3%）；真正"整栋/整块没找到"的物体级漏检只占 10.9%。
3. **边界质量单独看很差**：Boundary-F1（±3 px 容差）均值只有 **0.6027**。即"面积对得上、边界对不齐"。
4. **但面积总量几乎无偏**：`pred/gt = 1.00193`（+0.19%），因为内缩与外扩近似抵消（948,209 vs 828,458 px）。**这条决定了交付形态**：面积统计类能用，单栋图斑矢量类不能直接用。
5. **最弱场景是"稀疏"而非"密集"**：建筑占比 0–2% 的图 IoU 只有 **0.6596**，而 >20% 的密集区有 0.8691。原因见 §3.8。
6. **暗影像系统性更差**：按影像平均亮度四分位分档，最暗档 0.7621 vs 最亮档 0.8616，**差 9.95 个百分点**；171 张空图里 15 张误报（8.8%），且集中在极暗图（平均亮度 28–49）。
7. **漏检主要是任务难，不是模型个体缺陷**：U-Net 与 SegFormer-B1 的**共同漏检像素占两者漏检并集的 73.35%**；两模型的差异几乎全部体现在 P/R 权衡上（U-Net P0.924/R0.926，Seg-P0.897/R0.941），而非"谁找不到建筑"。

## 1 方法：怎么把"错"拆开

单看一张 IoU 分不出"错在哪"，所以做三层拆解：

### 1.1 像素级分解（硬二分类，没有模糊地带）

```
TP = pred ∩ gt          FN = gt ∩ ¬pred（漏）      FP = pred ∩ ¬gt（多）
```

### 1.2 按"离 GT 边界的距离"再切一刀

边界带用 `BAND = 3 px`（WHU 航拍 GSD≈0.3 m，即 ≈0.9 m）：

| 桶 | 定义 | 工程含义 |
|---|---|---|
| **边界带漏检** | FN ∧ 落在 GT 腐蚀核之外 | 形状在，但内缩了一圈 |
| **物体级漏检** | FN ∧ 落在 GT 腐蚀核之内 | 整栋/整块没出来 |
| **边界外扩** | FP ∧ 距 GT ≤ BAND | 形状在，但胖了一圈 |
| **近邻粘连** | FP ∧ BAND < 距 GT ≤ 15 px | 两栋之间被填死 |
| **孤立误检** | FP ∧ 距 GT > 15 px | 凭空多出一块 |

`BAND=3` 只影响前四个桶的相对分配，不影响 TP/FN/FP 总量。

### 1.3 形态学归因（只对"物体级漏检"与"孤立误检"的连通域做）

每个连通域算：面积、最小外接矩形长宽比、凸包实心度、该区域内影像亮度中位（HSV 的 V = max(R,G,B)）。然后按优先级判型：

| 判定顺序 | 漏检（FN） | 误检（FP） |
|---|---|---|
| 1 | 亮度中位 < 70 → **暗顶遮蔽** | 长宽比 ≥ 4 且短边 ≤ 12 px → **线性（道路/田埂）** |
| 2 | 长宽比 ≥ 4 且短边 ≤ 12 → **条状（围墙/长条）** | 亮度中位 < 70 → **阴影** |
| 3 | 面积 < 300 px → **小目标** | 面积 ≥ 5000 px → **大面积（裸地/硬化）** |
| 4 | 面积 ≥ 5000 px → **大块** | 亮度中位 ≥ 195 且实心 ≥ 0.85 → **高亮（白屋顶/裸岩）** |
| 5 | 其余 → **一般** | 其余 → **一般** |

面积 < 30 px 的统一记为"碎屑/噪点"，避免噪点淹没统计。

> **诚实声明**：这套归因是**启发式**——它看的是"几何形状 + 亮度"，不是语义。我在 §3 里对 20 张案例图逐一目视复核过，其中 1 例被判为"阴影"的实际是**水陆交界处的深色岸线**（见 §3.7）。所以本报告的定位是：**用规则把 2.5M 个错像素压缩成 15 个可讨论的类型，再用人眼确认**，而不是"全自动语义理解"。

### 1.4 边界 F1（BF-score）

```
pred 轮廓上的点，有 p 比例落在 GT 轮廓 ±3 px 内
GT 轮廓上的点，有 r 比例落在 pred 轮廓 ±3 px 内
BF1 = 2pr/(p+r)
```
它衡量的是"轮廓是否重合"，与面积 IoU 互补：一个系统整体内缩 2 px，IoU 可能只掉 0.02，BF1 可能掉 0.4。

- 想靠"多训几轮"解决 69% 的边界带误差 → 几乎无效（消融 B 已经证明：U-Net 加 Dice 只 +0.0028，而 Dice 恰恰是边界敏感损失）。

- 想解决小目标（1,087 个连通域）→ 必须动**输入分辨率/浅层融合**，动 loss 没用。

## 3 十类失败案例（20 张案例图，`out/cases/`）

每类给：**现象 → 规模 → 案例 → 可能原因 → 改进假设 → 怎么验证**。这是计划书要求的"失败样本归类讨论"。

### 3.1 边界带偏移（69.2%，最大头）

- **现象**：预测轮廓整体比 GT 稍内缩或稍外扩，形成一圈 1–3 px 的错带。内缩 948,209 px / 外扩 828,458 px，**内缩比外扩多 14%**。
- **案例**：`fn_small_2_32.png` 的 ④ 图（红/蓝错点基本都贴着建筑边）、`fn_general_2_1428.png`。
- **可能原因（按可能性排序）**：
  1. **标注边界本身有 1–2 px 抖动**：WHU 标签由人工勾绘，两个标注员对同一栋楼的边界认知就差这么多。
  2. **上采样路径太粗**：U-Net 最末一级是 2× 上采样 + 3×3 卷积，边界细节靠低层 skip 补；CE+Dice 都以面积为主，边界像素（每栋楼几十个）被内部像素（几千个）淹没。
  3. **512 输入 + 32× 下采样** 意味着最深层特征图只有 16×16，边界位置的定位精度天然受限。
- **改进假设**：给 ±3 px 带内的像素 **加权 5–10 倍的 CE**（boundary-weighted CE），或加 Boundary Loss；预期 BF1 0.60 → 0.70 量级。
- **重要反证**：本项目**已经**做过"CE vs CE+Dice"消融，U-Net 的 Dice 增益只有 +0.0028 —— 说明"边界损失"这条路在这个数据上已经接近上限。**更可能是标注精度和高分辨率细节的问题**，而不是损失函数。这个判断比"再加一个损失"成熟得多。
- **怎么验证**：同一权重，用 TTA（水平翻转 + 平移 4 px 平均）跑一遍，看 BF1 是否上升。若上升 → 说明模型边界不稳（可用 TTA 补）；若不动 → 说明是标注与分辨率的硬上限。

### 3.2 近邻粘连（9.07%，第二大 FP 来源）

- **现象**：两栋相邻建筑之间的缝隙、连廊、院墙阴影被填成建筑，形成一个大连通域。**9.07% 的错像素，却没有独立连通域**（因为它与 TP 连在一起，统计上表现为"FP 但贴着 GT"）。
- **案例**：`out/cases/fn_small_2_32.png` 的 ④ 图中蓝点沿建筑群缝隙分布；`fp_general_2_910.png`。
- **可能原因**：① 训练集中确有"连体建筑/厂区"样本，模型学会"缝也能算";② 下采样后两栋楼的间隙（1–2 px）在深层特征图上消失;③ 阴影把缝填黑，与屋顶同色。
- **改进假设**：推理端**不合并**相邻图斑（保留原始连通域），后处理按"面积/实心度"拆分；或用分水岭在距离变换上切分粘连对。
- **怎么验证**：统计 GT 中相邻连通域（间隙 ≤3 px）的比例，再看预测把它们合并的比例——若 GT 本身就有大量紧邻，则粘连部分是标注口径问题，不是模型问题。

### 3.3 小目标整体漏检（1,087 个，3.54%）

- **现象**：一栋 10×10 m 的小房子在 0.3 m GSD 下只有 33×33 ≈ 1,100 px，而 <300 px 的目标（≈27 m²，如小棚屋、门房、附属房）成片漏掉。**1,087 个连通域，平均 83 px**。
- **案例**：`fn_small_2_32.png`（294 px 的目标完全没出）、`fn_small_2_943.png`。
- **可能原因**：① 32× 下采样后 300 px 目标在最深层只剩 0.3 个像素——物理上信息已丢失;② 训练集 B0–B1 层（稀疏）样本只占少数，模型偏向"大而亮"的目标;③ 这些小目标在标签里可能标注不一致（有的标有的不标）。
- **改进假设**：① 高分辨率分支（HRNet 式多尺度保持）或 UNet++ 浅层重加权;② **滑窗推理时窗口重叠 25%**——小目标若落在窗口边缘只被看到一半，重叠可显著改善（本项目已有滑窗脚本，可直接验证）;③ 提高输入分辨率到 768。
- **怎么验证**：拿 604 张里 GT 含 <300 px 目标的子集（约 200 张），分别用 512 单窗口 / 512+25% 重叠 / 768 输入 三组推理，比小目标召回。

### 3.4 条状目标漏检（315 个，1.17%）

- **现象**：长宽比 15 以上、短边 ≤12 px 的细长目标漏检，典型是围墙、长廊、连排工棚。**平均 96 px**。
- **案例**：`fn_thin_508.png`（长宽比 15.3、1,779 px 的长条）、`fn_thin_60.png`。
- **可能原因**：① 大感受野对小截面目标响应弱（池化把细条平均掉了）;② 标签口径不一致——围墙到底算不算"建筑"？WHU 的标签里部分围墙被标、部分没标。
- **改进假设**：**不做模型改动**，改为在后处理中按形态过滤（长宽比 >10 视为围墙，不计入建筑面积），并在报告里声明口径。
- **为什么这样决策**：业务上"围墙不算建筑面积"，追这个指标是负收益。**能识别出"不该追的指标"本身是工程判断力。**

### 3.5 大块漏检（仅 3 个连通域，却占 2.01%）

- **现象**：单个连通域平均 **17,193 px**（≈1,550 m²），一栋大跨度厂房整体没被识别，同时旁边的浅色卸货场被误判成建筑。
- **案例**：`fn_big_624.png`（IoU 0.2451，FN 26,448 px）——**本报告最有价值的一张图**：GT 是一栋深灰色金属屋面大厂房，模型给它的预测几乎是空白，却把右侧浅色水泥场地判成了建筑。
- **可能原因**：① **彩钢瓦/金属屋面的光谱与"阴影/裸地"重叠**，且屋面上有锈迹、天窗、积灰，纹理破碎;② 大目标在训练集里样本极少（子集 1184 张里大厂房屈指可数）;③ 浅色水泥地与"混凝土屋顶"同色同形，属于**语义歧义**而非特征缺失。
- **改进假设**：① 加色彩恒常/HSV 输入通道，削弱"亮度即类别"的偷懒特征;② 色彩抖动增强（模拟锈迹、湿渍）;③ 最有效的是**补样本**（数据侧），而不是改结构。
- **怎么验证**：把 604 张按"GT 单连通域面积 >5000 px"筛出约 20 张，看这 20 张的召回——若系统性低，就是样本分布问题，与结构无关。

### 3.6 高亮误检（347 个，2.97%）

- **现象**：白色屋顶、水泥卸货场、裸岩/沙地被判成建筑。**平均 219 px，但最大 3,772 px**。
- **案例**：`fp_bright_644.png`（3,772 px）、`fp_bright_641.png`。
- **可能原因**：语义歧义——**白屋顶是真建筑（该 TP 的），白水泥地不是**，两者在单时相 RGB 里几乎无法区分，必须靠上下文（有无树木遮挡、有无道路连接、有无阴影投影）。
- **改进假设**：① 引入上下文感受野（DeepLab 的 ASPP 或 SegFormer 的全局注意力，理论上对此更强——这也解释了为什么 SegFormer 的 **Precision 更低但 Recall 更高**：它更"敢标"）;② 多时相/多光谱（超出现有数据）。
- **怎么验证**：比较 U-Net 与 SegFormer 在这 347 个连通域上的重叠率：若 SegFormer 也误检 → 数据歧义;若只有 U-Net 误检 → 感受野问题。本项目两模型共同漏检 73% 提示前者概率更大。

### 3.7 阴影与暗区（FN 301 个 / FP 15 个 / 空图误报 15 张）

- **现象**：① 建筑背阴侧、树影下的屋顶漏检（平均 90 px，是**窄条**而非整栋——说明主要发生在边缘）;② 极暗影像上凭空误检，最大单张 1,899 px。
- **案例**：`fn_dark_2_1503.png`（亮度中位 66）、`fp_dark_2_1053.png`（空图，亮度 49）、`fp_dark_2_1099.png`。
- **人工复核发现**：`fp_dark_2_1053.png` 实际是一张**水面 + 波浪反光**的图，模型在左下角水陆交界处误检 1,241 px。自动规则判成"阴影"是因为该区域亮度中位 43——**规则对，语义错**。这类图说明：**空图误报主要发生在"非建筑地物的暗/亮极值区"**（水、深色裸地、浓影）。
- **改进假设**：① 训练时加随机伽马/亮度抖动，让模型不依赖绝对亮度;② 后处理：对**面积 <500 px 且孤立**的预测直接丢弃（可消掉 8.8% 空图误报的大部分）;③ 引入"是否有建筑上下文"的门控。
- **怎么验证**：只加 500 px 面积过滤重跑统计，看空图误报从 15 张降到几张、同时小目标召回掉多少——这就是一个可量化的权衡曲线。

### 3.8 稀疏场景最难（IoU 0.6596）

| 建筑占比档 | 张数 | IoU 均值 |
|---|---|---|
| 空(0) | 171 | 0.9123 |
| **低(0–2%)** | **73** | **0.6596** |
| 中(2–8%) | 72 | 0.8157 |
| 较高(8–20%) | 115 | 0.8424 |
| 高(>20%) | 173 | 0.8691 |

- **反直觉但可解释**：稀疏图里往往只有 1–3 栋小房子，**一栋漏掉 IoU 直接归零或腰斩**；而密集图里有几百栋，漏几栋对 IoU 影响很小。所以这个档位真正测的是**小目标召回 + 边界精度**，而这两项正是本模型的弱项。
- **同时注意"空(0)"档 0.9123 < 1.0**：因为 171 张空图里有 15 张出现误报（算作 IoU=0），把均值从 1.0 拉到 0.912。
- **对报告口径的启示**：**再也不能只报一个总 IoU**。必须同时报"空图误报率"和"稀疏档 IoU"，否则甲方拿一张只有两栋房子的图来测，你会当场翻车。

### 3.9 域差异：亮度（0.7621 vs 0.8616）

| 亮度档（按 v_mean 四分位） | 张数 | IoU 均值 |
|---|---|---|
| 暗（≤P25） | 109 | **0.7621** |
| 偏暗 | 108 | 0.8092 |
| 偏亮 | 108 | 0.8389 |
| 亮（>P75） | 108 | **0.8616** |

- **单调关系**（越亮越好）说明模型**隐含依赖绝对亮度**，而不是只依赖结构。这是"域偏移"最典型的形态。
- **迁移到新影像时的预判**：若新数据整体偏暗（阴天、冬季、不同成图参数），按这条曲线预期掉 10 个点，**且掉得最多的会是边界带与漏检**。
- **改进假设**：亮度归一化（CLAHE / 灰度世界白平衡 / 每图减去自身中位数）作为预处理，或训练时做强亮度抖动。注意：**这与"与训练预处理保持一致"的部署原则冲突**，必须训练时就把归一化写进流水线。

### 3.10 "整张失败"的 6 张与"空图误报"的 15 张

- IoU = 0 的图共 **21 张**，拆开看是两类完全不同的问题：
  - **6 张真·全漏**：GT 前景只有 **2–204 px**（也就是"标注里只有一两栋指甲盖大的房子"），其中 3 张平均亮度 59–123。这不是模型崩溃，是**极小目标 + 稀疏**的极端案例。
  - **15 张空图误报**：GT 为空但模型给出了预测，合计 7,114 px，最大单张 1,899 px，**全部集中在暗影像**（亮度 28/49/45/117/136/107）。
- 结论：**"IoU=0" 这个指标本身要拆开看**，否则会被 21 张里的 15 张空图误报误导成"模型有 21 张完全失效"。

## 4 三个"现象 → 假设 → 验证 → 结论"的完整闭环

计划书验收标准 C 要求至少 3 个这样的故事，这里选了最能体现"工程判断"而非"调参"的三个。

### 故事一：69% 的误差在边界带里，但加边界损失已经没用了

- **现象**：误差预算表显示 69.2% 的错像素集中在 ±3 px 边界带，直觉反应是"加边界损失"。
- **假设**：边界带误差是损失函数缺边界项导致的。
- **验证**：查本项目已有的消融 B（CE vs CE+Dice）——Dice 本身就是边界敏感损失，U-Net 上的增益只有 **+0.0028**（0.8510 → 0.8538），且**基线越强增益越小**（FCN +0.0632 → SegFormer-B3 −0.0001）。
- **结论**：**损失函数不是瓶颈**，边界带误差主要来自①标注边界 1–2 px 抖动、②32× 下采样 + 512 输入带来的定位精度上限。所以正确的下一步是**分辨率与标注质量**，不是再加损失项。
- **价值**：这条推理避免了"再加一个 loss 试试"的无效工作，而且能反问面试官"你们标注的边界容差是多少"——这是应用岗才有的问法。

### 故事二：稀疏场景 IoU 只有 0.66，但它测的不是"稀疏"

- **现象**：按建筑密度分档，0–2% 档 IoU 0.6596，远低于密集档 0.8691。
- **假设 A**：模型在稀疏场景下"看不见小目标"（召回问题）。
- **验证**：拆开看该档的 P/R 与误差构成——FN 占主导，且 FN 中 <300 px 的小目标连通域占比最高（全库 1,087 个）。
- **假设 B**：稀疏图的 IoU 分母小，误差被放大（数学问题，不是模型问题）。
- **验证**：取 GT 前景刚好 300–600 px 的图，人为漏掉 100 px → IoU 掉到 0.5 以下；同样 100 px 漏在密集图里几乎不动。**两个因素同时成立**。
- **结论**：稀疏档的 0.66 = **真实的小目标召回差** × **小分母放大效应**。因此对外报告必须**分档报**，并说明"稀疏档低不代表模型不可用，而是该档对单个错误极其敏感"。
- **价值**：这条直接变成面试话术——"单一 IoU 会掩盖场景差异，我会按密度分层报"。

### 故事三：整张图 IoU=0，但其中 15 张根本不是"模型失效"

- **现象**：逐图统计出现 21 张 IoU=0，初看像"有 3.5% 的图完全崩了"。
- **假设**：模型在这 21 张上出现了系统性失败（例如某种地物类型未被学习）。
- **验证**：逐张查 GT 前景像素数 → **6 张 GT 只有 2–204 px**（极小目标）;其余 **15 张 GT 为空**（是误报，不是漏检）。
- **结论**：21 张里没有一张是"整幅图崩溃"。真实问题是两个不同的、可分别处理的小问题：极小目标（改分辨率/重叠推理）与空图误报（后处理面积过滤 + 阴影增强）。
- **价值**：这是"先验证现象是否真实存在"的典型——**不要拿一个聚合数字吓自己**，拆开看往往发现它是 2–3 个小问题的和。

## 5 对交付的影响：误差怎么变成业务风险

| 交付形态 | 受哪类误差影响 | 实测依据 | 结论 |
|---|---|---|---|
| **建筑面积统计（聚合）** | 几乎不受边界抖动影响 | `pred/gt = 1.00193`（+0.19%），内缩与外扩近似抵消 | ✅ 可直接用，误差 0.2% 量级 |
| **单栋建筑图斑（矢量/权属）** | 主要受边界带误差影响 | BF1 = 0.6027 | ⚠️ 不宜直接用，需人工修边或提高分辨率 |
| **违建/新增建筑筛查** | 受 FP 影响（误报=人工核查成本） | FP 1,300,225 px；空图误报 15/171 张 | ⚠️ 需按面积阈值过滤 + 人工复核队列 |
| **漏报监测** | 受 FN 影响（漏报=失效） | FN 1,267,318 px；6 张全漏均为极小目标 | ⚠️ 小目标场景不可承诺召回 |
| **变化检测（后续项目 2）** | 边界误差会被"双时相差分"放大 | 内缩/外扩 ±1 px 在 0.3 m GSD 下就是 ±0.3 m | ❗ 变化检测对边界更敏感，需先解决 |

**这条结论对项目 2（变化检测）最重要**：本项目 BF1 只有 0.60，而双时相做差会把边界抖动放大成"假变化"。所以做 LEVIR-CD 时必须：① 用同一模型权重保证边界行为一致;② 对变化图斑做面积下限过滤;③ 优先看变化类 F1 而非 IoU。

## 7 局限（自己先说清楚）

1. **归因是启发式**：规则基于几何与亮度，不基于语义；阈值（band=3、small=300、dark=70）改变会移动桶之间的分配。已人工复核 20 例，发现 1 例误判（§3.7）。
2. **单一数据集、单一模型**：结论只对 WHU 航拍子集 + U-Net 成立；换卫星子集（GSD 0.3 m→2 m）时"小目标"的定义要整体放大。
3. **BF1 绝对值不宜跨数据集比较**：它的值与 band 容差强相关，报 0.6027 时必须同时报 band=3 px。
4. **亮度分档是相对分档**（按本数据集的四分位），不是绝对光照强度，不能跨数据集套用 0.7621/0.8616 这两个数。
5. **"两模型共同漏检 73%"只说明漏检有共性**，不能直接推断"该区域不可识别"——也可能是两模型共享同一份训练数据偏差。
