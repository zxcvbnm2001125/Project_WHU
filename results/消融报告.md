# W3 消融实验报告

**主题**：消融 A（四模型结构对比）+ 消融 B（CE vs CE+Dice）
**数据**：WHU 建筑提取 · 固定子集 train 1184 / val 474（test 604 留出未用）
**口径**：输入 512×512 · 25 轮 · seed 11 · 评测为**全验证集全局混淆矩阵** · 单卡 RTX 4060 Laptop 8GB

> 只比相对优劣，绝对值不跨子集比较。
> 本报告所有数字都可追溯到 `XR_1` / `XR_2` 的 `run/train/<exp>/` 逐轮 CSV 与 `XR_1/参数.xlsx`。

---

## 0 摘要

1. **结构对比的赢家是 U-Net 与 SegFormer，不是 DeepLabV3+。** 前景 IoU：U-Net R50 **0.8802** > SegFormer B2 **0.8758** > B1 0.8727 > B3 0.8710 >> DeepLabV3+ R101 0.7220 > R50 0.7087 > FCN R50 0.6583。
2. **工程部署的赢家是 SegFormer B1，而且赢得没有悬念**：13.68M 参数（U-Net 的 1/3.2）、延迟 **9.42 ms**（U-Net 的 1/3.06、比 DeepLab R50 还快 1.54 倍）、吞吐 **96.8 img/s**、显存 1566 MB（U-Net 的 67%），前景 IoU 只低 **0.0075**。即"精度冠军"和"部署冠军"是两个模型，不是一个模型两项全占。
3. **DeepLabV3+ 掉到 0.71–0.72 是配置问题，不是结构问题**（见 §2.5），四条原因都可核查。
4. **Dice 的收益强烈依赖基线强度**：FCN +0.0632、DeepLab 家族 +0.051~0.057、SegFormer +0.011~0、U-Net +0.003。基线越低增益越大，呈单调关系。
5. **mIoU 会把结构差距压缩**：U-Net 与 SegFormer B2 的 mIoU 只差 0.0027，前景 IoU 差 0.0044；而 FCN 与 U-Net 的 mIoU 差 0.1271、前景 IoU 差 0.2219。**必须两个数一起报**，否则 FCN 的失败会被背景掩盖。

### 1.3 评测口径：全局混淆矩阵

四个工程原始的验证聚合方式各不相同，直接抄 CSV 会得到互相矛盾的数字。本报告统一改为**把整个验证集的预测累加进一个 2×2 混淆矩阵再算指标**：

- 空图（gt 无前景、pred 也无前景）落在 0/0，`nanmean` 跳过——不奖不罚；
- 误检正常计 FP——该罚就罚；
- 与 DeepLab 自带的 `StreamSegMetrics` 同一套公式。

同一份 U-Net 权重、同一份 val 474，三种口径的结果：

| 口径 | U-Net 前景 IoU | FCN 前景 IoU |
|---|---|---|
| 逐批平均（U-Net 原生） | 0.8538 | 0.4034 |
| 逐图平均、空图记 0（FCN 原生，val bs 写死 1） | 0.5799 | 0.4034 |
| **全局混淆矩阵（本报告）** | **0.8802** | **0.6583** |

FCN 被原生口径压掉了 0.25 个点——它本身确实最差，但没有 CSV 里看起来那么差。

### 1.4 硬件与速度测量

RTX 4060 Laptop 8GB，`torch.inference_mode()`、固定随机张量 512×512、5 次预热。延迟取 bs1、吞吐与显存取 bs8 峰值。**显存是推理峰值，不是训练峰值。**

**速度上的四个反直觉结论**：

1. **U-Net 的推理显存是 DeepLab 的 2.4 倍**（bs8：2348 vs 966 MB；bs1：452 vs 266 MB），延迟也慢一倍。原因是 unetUp 要在 512 全分辨率上做多次上采样与跳跃拼接，而 DeepLabV3+ 用 OS16 把特征图缩到 1/16 再一次性上采样。
2. **SegFormer B1 是全表最快的，而且快得不讲道理**：9.42 ms，比 U-Net 快 **3.06 倍**、比 DeepLab R50 还快 1.54 倍，显存只有 U-Net 的 54%（bs1：243 vs 452 MB），参数 13.68M（U-Net 的 1/3.2），精度只低 0.75 个点。原因是 MiT 主干第一层就是 stride-4 的 patch embed，特征图面积直接缩到 1/16 才开始算，而 U-Net 全程在 512×512 上做卷积。**所以"参数量小"和"跑得快、省显存"在这张表上是同一件事，不是权衡。**
3. **参数量与速度不同向**：DeepLab R50（39.76M）比 SegFormer B2（24.72M）参数多 61%，但延迟低 8%（14.47 vs 15.79 ms）——因为它靠 OS16 把计算压在小分辨率上；而 FCN（32.95M，纯卷积）反而是全表最慢。**决定速度的是"在多大分辨率上算"，不是"有多少参数"。**
4. **SegFormer 加大规模是纯亏**：B1 → B3 参数 3.26 倍（13.68 → 44.60M）、延迟 2.62 倍（9.42 → 24.65 ms）、单图显存 +48%（243 → 360 MB），而前景 IoU 反而降了 0.0017（0.8727 → 0.8710）。**在 1184 张 / 25 轮的预算下容量已经过剩，加参数只买到延迟。** 这条直接回答了"该不该上大模型"。注：B3 的权重来自那次 23 轮中断的训练，多给 2 轮也补不回 2.6 倍延迟，但引用时须注明这个口径差。

### 2.4 结论

- **精度**：U-Net 与 SegFormer 家族是一个梯队（0.871–0.880），DeepLabV3+ 与 FCN 是另一个梯队（0.66–0.72），中间有 0.15 的断层。
- **参数量效率**：SegFormer B1 用 13.68M 拿到 0.8727，是 U-Net 的 1/3.2 参数换 99.1% 的精度；B2 24.72M 拿 0.8758，是全场最优的性价比点。
- **帕累托前沿上只有两个点**：U-Net（0.8802 / 28.84 ms，精度端）与 SegFormer B1（0.8727 / 9.42 ms，速度端）。DeepLab R50 虽然快（14.47 ms）但精度掉 17 个点，落在前沿内部；FCN 两项都差。**换句话说：选型问题是"要那 0.75 个点，还是要 3 倍速度"，而不是"哪个模型更好"。**
- **SegFormer 三个规模之间几乎没有差别**（0.8710 / 0.8727 / 0.8758，跨度 0.0048，比 b3 与 b1 的参数差 3.3 倍）——说明在这个数据规模下**瓶颈不是模型容量，而是 1184 张训练样本与 25 轮预算**。这条结论对"该不该上大模型"有直接指导意义。
- **FCN 最差是结构性的**：没有跳跃连接、没有多尺度上下文聚合，25 轮短训练下前景 IoU 只有 0.6583，相对 U-Net 差 25%。

### 2.5 DeepLabV3+ 为什么打不过 U-Net（面试必被问）

这不是"DeepLab 不行"，四条原因都可核查：

1. **学习率大了一个数量级**：DeepLab 用 `1e-3`（backbone 0.1×），U-Net / FCN 用 `1e-4`。DeepLab 官方配置是给 bs16 / crop513 / 上万 iter 的 COCO+VOC 训练用的，挪到 1184 张 / bs8 上偏激进。
2. **总迭代预算太小**：PolyLR 的 `total_itrs = epochs × len(train_loader)`（`XR_2\DeepLabV3Plus\train.py:108`），bs8 下 148 iter/轮 × 25 轮 = **3700 步**，power=0.9 的 poly 曲线到 3700 步就走完了。DeepLab 官方 recipe 是 30k–60k 步，这里只有 1/10。
3. **OS16 的上采样太粗**：512 输入经 OS16 只剩 32×32，边界恢复全靠一个 4× 上采样 + 低级特征融合。建筑边界是这次任务的主要误差来源，这个设计在 25 轮内学不出精细边界。
4. **分类头重初始化**：VOC 21 类预训练的 `classifier` 被整个换掉（`num_classes=2`），预训练里最有判别力的部分没继承下来，等于在 3700 步里重新学一个解码头。

**可验证的推论**：如果把这四条改掉（lr 降到 3e-4、bs8 下把轮数提到 60–80 轮、改 OS8、或干脆冻结 backbone 先训解码头），DeepLabV3+ 应该能追上 U-Net。**这是本项目最值得补的一组实验，也是最容易被追问的薄弱点。**

### 3.3 结论：Dice 的收益与基线强度负相关

把 8 对按 CE 臂基线从低到高排，Δ 单调递减：

```
FCN 0.4034 → +0.0632
Xception 0.6844 → +0.0570
R50 0.7087 → +0.0524
R101 0.7220 → +0.0514
U-Net 0.8510 → +0.0028
Seg B1 0.8609 → +0.0118
Seg B2 0.8646 → +0.0112
Seg B3 0.8711 → −0.0001
```

这条曲线是本消融最有价值的产出，它比"平均提升 +0.03"有用得多，因为**它能预测新任务上该不该加 Dice**：

- 基线前景 IoU < 0.75（模型还没学会把前景从背景里分出来）→ **加 Dice，稳定 +0.05~0.06**；
- 基线 0.85–0.87（已经收敛到架构上限）→ 加 Dice 基本无效，白花时间；
- 基线 > 0.87 → 甚至会微负（B3 的 −0.0001，在噪声范围内，但足以说明"没收益"）。

### 3.4 为什么高基线上 Dice 就失效了

四个原因，从强到弱：

1. **加权 CE 已经做了 Dice 的工作**。SegFormer 两臂都用了类别权重 `1,3`，把前景的损失放大 3 倍——这正是 Dice 想解决的类别不平衡。两者功能重叠，叠加不产生新信息。
2. **软 Dice 对边界不敏感**。它优化的是区域重叠率，在二分类下与 IoU 高度相关，梯度形式是"整体重叠的比值"，不区分内部像素与边界像素。当前景 IoU 到 0.86 以上，剩下的误差几乎全是边界像素（建筑边缘 1–2 个像素宽），Dice 的梯度在这些位置被大面积正确区域稀释掉了。
3. **梯度饱和**。Dice 的梯度 ∝ 1/(预测和+真值和)，当重叠已经很高时分母很大、梯度趋零，实际学习信号被 CE 主导。
4. **瓶颈不在损失函数**。SegFormer B1/B2/B3 三个规模的精度跨度只有 0.0048，说明这个数据规模下模型已经到顶——换损失、加容量都没用，只有加数据或加轮数有用。

**面试话术**：Dice 不是万能提分项，它在"前景被背景淹没、模型欠拟合"时收益最大；当模型已经把前景 IoU 推到 0.86+，瓶颈转移到边界精度与标注噪声，Dice 的边际收益趋零。所以消融 B 必须**分模型报**，给一个"平均提升"是错的。

### 3.5 bs8 vs bs6 的混杂有多大

DeepLab 那两对（R50 / R101）的 CE 臂是 bs8、Dice 臂是 bs6，看着不公平，但影响方向已经量化：

- **bs 本身影响很小**。同轮数下数据曝光完全一样（1184 张 × 25 遍），bs 只改更新次数与梯度噪声。**最硬的证据**是 SegFormer B3：bs8/23 轮 0.8710 vs bs4/25 轮 0.8711，bs 差一倍、轮数差两轮，结果差 **0.0001**——bs 噪声量级在千分之一。
- **但 DeepLab 的 bs 偷偷改了学习率预算**。PolyLR 的 `total_itrs = epochs × len(train_loader)`，bs8 → 3700 步，bs6 → 4925 步（**+33%，多 1225 次更新**）。bs8 跑完 3700 步时 LR 已触底 1e-6，而 bs6 在同一时刻还停在 `1e-3 × (1−3700/4925)^0.9 = 2.87e-4`，后面还有 1225 步"中低 LR 精修"。方向上对 bs6 有利。
- **反证：这个偏袒没有发生**。DeepLab 家族唯一完全干净的对照是 Xception（两臂都 bs4、都 25 轮），Δ = **+0.0570**；而带 bs6 优势的 R50/R101 只给出 +0.0524 / +0.0514——**比干净对照更小**。如果 bs6 真的系统性偏袒 Dice 臂，脏对照应该更大而不是更小。

**结论**：DeepLab 的真实 Dice 增益约 +0.05~0.057，bs 混杂带来的偏差估计 <0.005（约为效应量的 1/10），不影响结论方向。可以不重跑，但表里必须写明 bs 差异并附上这段交叉验证——**"知道自己的混杂因素在哪、并且做了反证"本身就是加分项**。

## 4 口径与可信度

### 4.1 为什么消融用子集（面试考点 10）

公平对比原则：**同数据 / 同轮数 / 同种子**。

- 本机只有一张 RTX 4060 Laptop 8GB，全量 4262 张 × 50 轮约 4 小时/次，四模型 × 两臂 = 8 次 = 32 小时，迭代不起。
- 子集方案把单次训练压到 ~1.4 分钟/轮、25 轮约 40 分钟，8 个臂一天内跑完，能快速试错。
- 子集不是随机切，而是**按前景占比分层**（5 层，各层偏差 ≤0.11%），保证 train 与 val 的前景分布一致。
- **代价与边界**：绝对指标低于全量训练的结果，所以**只比相对优劣，绝对值不跨子集引用**。表头必须注明「子集 1184 / 25 轮 / seed 11」，否则数字无法复现也无法解释。

### 4.2 为什么必须同时报前景 IoU 和 mIoU（面试考点 11）

二分类里背景占比极高（val 平均建筑像素只占约 10%），背景 IoU 恒在 0.95+：

- FCN 的 mIoU 是 0.8051，看着"还行"；但拆开是背景 0.9518 + 前景 0.6583，**前景只到 0.66，三分之一建筑没提出来**。
- mIoU 会系统性地压缩结构差距：FCN → U-Net，mIoU 提升 0.1271，前景 IoU 提升 0.2219，**真实差距是 mIoU 显示的 1.75 倍**。
- 反过来，U-Net 与 SegFormer B2 的 mIoU 只差 0.0027（几乎并列），但前景 IoU 差 0.0044——mIoU 在这里也没失真，因为两者背景都很好。

**一句话**：mIoU 高不代表建筑提取好，它可能只是背景分得好。建筑提取任务必须报前景 IoU。

### 4.3 已知混杂与局限（必须主动交代）

| # | 问题 | 影响 | 处理 |

# 训练（以 XR_1 消融 A 为例）

  --xr-root XR_1 --split val --json-out out.json
