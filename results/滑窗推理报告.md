## 0 结论

1. **对 512×512 瓦片直接跑滑窗等于没跑**：窗口 = 整图，只剩 1 个窗口，重叠区为空，融合是恒等映射。所以先按 WHU 原始切片规则把 4×4 个连续瓦片拼回 **2048×2048** 大图，再验证。
2. **滑窗融合把接缝伪影基本消掉了**：跨缝跳变率 **11.66% → 1.15%（降 90.2%）**，接缝带（±2px）前景 IoU **0.7253 → 0.8240（+9.87 个点）**。
3. **代价只有 1.48×**：窗口数 16 → 25（冗余系数 1.562），耗时 0.64 s → 0.94 s。
4. **接缝带以外的精度几乎不变**（0.7977 → 0.7974，−0.0003）——这证明差异确实来自接缝处理，而不是模型或预处理被改动了。
5. **意外发现**：滑窗路径在接缝带上的 IoU（0.8240）反而**高于**它自己在非接缝区的 IoU（0.7974）。重叠区的多窗口融合本身就是一个轻量 ensemble，比单窗口预测更准。

## 1 为什么必须拼大图

`WUH_sub25` 与全量数据集的瓦片全部是 512×512。窗口设 512 时：

```
窗口数 = floor((512 - 512)/stride) + 1 = 1
重叠区 = ∅
融合   = 恒等映射
```

代码能跑通，但**没有验证任何东西**：接缝不存在，融合没被触发，加权窗口没用上。面试官问"你的滑窗验证了什么"，这个状态答不上来。

所以先造大图。好在 WHU 的瓦片是**从大幅影像顺序裁出来的**，可以拼回去——这一点我做了实测，不是假设：

| 检验 | 结果 | 结论 |
|---|---|---|
| 编号 n 与 n+1：右列 vs 左列像素差 | MAE **18.36**（随机两张对照 61.36） | n 与 n+1 **水平相邻** |
| 编号 n 与 n+k：下行 vs 上行，扫 k=1..259 | **k=64 时 MAE 18.48**，其余 k 全在 48–66 | n 与 n+64 **竖直相邻** |
| 官方 train 瓦片数 | 4736 = **64 × 74** | 交叉验证：行宽确实是 64 |

切片规则：

```
row-major，行宽 64，0-based
idx = row * 64 + col        row ∈ [0,73], col ∈ [0,63]
```

数据位置：`D:\[C]Remote_Sencing_Projection\Project_WUD\Deeplabv3+\WHU\train\{image,label}`
（`label` 是单数；同名的 `WHU_0` 只有 1070 张，是早期小实验，不是全量）

> 用全量数据而不是 25% 子集拼图：子集里 16 个指定 tile 同时存在的概率 ≈ 0.25¹⁶ ≈ 0，拼不出完整块。推理验证不需要训练数据，用全量完全正当。

**拼接方案最大的好处是自带 GT**：拼回来的大图有对应的大 mask，接缝改善可以**算**出来；真实遥感大图只能目视，没法量化。

## 2 三层验证协议

| 层 | 内容 | 判据 | 结果 |
|---|---|---|---|
| 1 退化测试 | 单张 512 瓦片走滑窗 | 窗口数 = 1，且与直接推理逐像素相同 | 窗口数 **1**，逐像素一致 **True** ✅ |
| 2 一致性测试 | 2048² 大图，逐瓦片硬拼 vs 滑窗融合 | 非接缝区几乎一致，差异只在接缝带 | 非接缝区 IoU 差 **−0.0003** ✅ |
| 3 接缝量化 + 目视 | 接缝带 IoU、跨缝跳变率、三联图 | 滑窗在接缝带显著更优 | **+0.0987**，跳变降 **90.2%** ✅ |

选中的块：`row 24..27, col 56..59`（前景占比 0.310，块内 std 0.158）。选块规则写死在脚本里——在候选块中挑"平均前景占比 0.10–0.35 且块内方差最大"的一块，避免整块空图让接缝指标退化成 0/0。

## 3 结果

### 3.1 主表

| 指标 | 逐瓦片硬拼 A | 滑窗融合 B | 差值 B−A |
|---|---|---|---|
| 前景 IoU（全图） | 0.7968 | 0.7978 | +0.0009 |
| **前景 IoU（接缝带 ±2px）** | **0.7253** | **0.8240** | **+0.0987** |
| 前景 IoU（接缝带以外） | 0.7977 | 0.7974 | −0.0003 |
| **跨缝跳变率** | **0.1166** | **0.0115** | **−0.1051（降 90.2%）** |
| 窗口数 | 16 | 25 | 1.56× |
| 推理耗时 (s) | 0.64 | 0.94 | 1.48× |

- 接缝带只占 **1.17%** 的像素，所以全图 IoU 只涨 0.0009；把它拆出来看才是 +9.87 个点。
- A/B 前景 IoU 一致性 0.9560，逐像素一致率 **98.78%**——两条路径整体高度一致，分歧集中在接缝。

### 3.2 逐线跨缝跳变率（竖线 x=512/1024/1536，横线 y=512/1024/1536）

| 线 | x=512 | x=1024 | x=1536 | y=512 | y=1024 | y=1536 |
|---|---|---|---|---|---|---|
| 逐瓦片 A | 0.1416 | **0.1875** | 0.0649 | 0.1387 | 0.1289 | 0.0381 |
| 滑窗 B | 0.0166 | **0.0103** | 0.0049 | 0.0132 | 0.0112 | 0.0127 |
| 降幅 | 8.5× | **18.2×** | 13.2× | 10.5× | 11.5× | 3.0× |

这就是"接缝伪影"最直接的量化：逐瓦片硬拼时，接缝两侧来自两个独立的推理窗口，线上有 **6%–19%** 的像素预测突变；滑窗融合后只剩 **0.5%–1.7%**。

## 4 实现要点（都是会踩的坑）

1. **在概率图上累加，绝不在 argmax 后的标签上平均。** `softmax → 概率×权重累加 → 除以权重和 → argmax`。对 0/1 标签平均会丢掉置信度，也没法做加权融合。
2. **stride = 512 × (1 − 0.25) = 384**，2048 图 → `floor(1536/384)+1 = 5`，即 5×5 = **25 个窗口**（不是 16）。冗余系数实测 1.562，理论渐近值 `1/(1−0.25)² = 1.778`（小图上贴边对齐使实际值更低）。
3. **边缘贴边对齐，不用 pad。** 最后一列/行的窗口起点取 `H−512`，与前一列重叠更多。pad 会引入灰边伪影（U-Net 的验证预处理正是灰 128 填充），还得额外维护有效区 mask。
4. **融合权重用汉宁窗，不用均匀平均。** `np.outer(hanning(512), hanning(512)) + 1e-3`，中心权重≈1、边缘≈0。理由：CNN 有 padding 效应，**窗口边缘的预测质量系统性偏低**，均匀平均会把边缘的坏预测平摊进接缝。加 1e-3 是防止角落权重为 0 导致除零。
5. **预处理必须与训练逐字一致，窗口内不再 resize。** 窗口本身就是 512，与训练输入同尺寸。U-Net 的验证预处理是「等比缩放 + 灰 128 填充 + `/255.0`」——对 512×512 窗口而言缩放与填充都是恒等，所以只剩 `/255`，**没有 ImageNet mean/std**。四个工程的归一化各不相同，搞错这一处，指标会莫名其妙掉几个点。
6. **窗口 batch 化。** 25 个窗口堆成一个 batch 送 GPU（这里 batch=8，分 4 批）。

## 5 面试话术（考点 5）

> **大图推理为什么需要 overlap？**
> CNN 有 padding 效应，窗口边缘的像素感受野不完整，预测质量系统性偏低。硬拼会在边界处出现断裂、错位、类别跳变。我在 2048×2048 的重建大图上量过：逐瓦片硬拼在接缝线上的预测跳变率是 6%–19%，接缝带前景 IoU 只有 0.725，比非接缝区的 0.798 低 7 个点。重叠让边界像素有机会以"中心"身份被重新预测一次。
>
> **融合方式有哪些？**
> ① 均匀平均（最简单，但把边缘的坏预测平摊进来）② 高斯/汉宁窗加权（工业界默认，中心权重大）③ 距离变换加权（等价思路，实现麻烦）④ 重叠区投票 / 取最大置信度。我用汉宁加权，接缝带 IoU 从 0.725 提到 0.824，跨缝跳变率降了 90%。
>
> **代价？**
> 25% 重叠 → stride 384 → 算力 ×1.78（渐近值），实测 1.48×，换来接缝处的稳定性。这是可调的工程折中。
>
> **怎么验证做对了？**
> 三层：单瓦片退化测试（必须只剩 1 个窗口且与直接推理逐像素相同）→ 大图一致性测试（非接缝区 A/B 差 −0.0003）→ 接缝量化（跳变率、接缝带 IoU）。只看"目视没接缝"是不够的，那是主观判断。

## 6 可直接粘进 README 的段落

> 本数据集瓦片均为 512×512，单瓦片推理不存在接缝问题。为验证滑窗与融合逻辑，按 WHU 原始切片规则（row-major，行宽 64，实测相邻编号瓦片边界像素差 18.4 vs 随机对照 61.4）重建 2048×2048 连续影像，对比「逐瓦片硬拼」与「512 窗口 / 25% 重叠 / 汉宁加权融合」两条路径：非接缝区前景 IoU 差异 −0.0003（两条路径等价），接缝带（±2px）前景 IoU 0.7253 → 0.8240（+9.87 点），跨缝预测跳变率 11.66% → 1.15%（降 90.2%），窗口数 16 → 25（1.56×），耗时 0.64 s → 0.94 s。

## 7 局限与下一步

| 项 | 说明 |
|---|---|
| 单模型 | 只验了 U-Net。DeepLab / SegFormer 的预处理不同（前者原图不缩放、后者等比+居中填充），换成它们要改 `make_infer` 里的归一化 |

| 绝对 IoU 低于 val | 该块前景占比 **31%**，远高于验证集均值（约 10%）——密集区边界更多、更难。0.797 vs 0.8802 是数据难度差异，不是滑窗的问题 |
| 未接 GeoTIFF | 大图拼接目前只在内存里做。W4 的"写回 GeoTIFF 保留仿射变换"要把 `make_mosaic` 换成 `rasterio` 的 windowed read/write |
| 未做面积过滤后处理 | W3 的下一条任务（阈值 + 小连通域过滤），会改变接缝带指标，应在那之后再复测一次 |
